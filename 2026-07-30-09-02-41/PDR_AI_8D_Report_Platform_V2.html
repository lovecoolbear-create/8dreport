0 V2.0 修订说明

  • [策略调整 1] 多模态输入聚焦图片+邮件解析，视频分析暂缓至 Phase 2+，降低 MVP 成本和复杂度。
  • [策略调整 2] 历史 8D 报告结构化采用 LLM-as-ETL 方案：用便宜大模型（DeepSeek/Qwen）+ JSON Schema 自动提取，替代传统正则/NER 方案，增加 jsonschema 校验+重试防御层。
  • [策略调整 3] 5-Why 根因推演增加三项硬约束：① 强制证据链绑定（每条推论必须引用来源）② 置信度三级标注（confirmed / inferred / speculative）③ 推测项自动触发补充资料清单。
  • [策略调整 4] 责任判定改为 AI 建议 + 单选确认框 + 人工决策 模式，AI 不越权。
  • [策略调整 5] 工作流从"两步法"升级为 分步确认工作流，每步确认后数据才流入下一步，避免连锁返工。
  • [时间线修正] 基于实际开发复杂度，Phase 1 调整为 3-4 周，Phase 3 调整为 2-3 个月。

1 项目背景与目标

1.1 业务痛点

  • 效率低下：传统客诉处理与 8D 报告撰写过程漫长，信息散落在邮件、图片及各类检测报告中，整理与推演归因耗时耗力。
  • 质量参差不齐：团队成员经验差异大，初级 QA 难以精准判断根本原因与责任方，容易导致责任推诿或措施不到位。
  • 经验无法沉淀：历史优秀 8D 案例与行业标准未有效转化为生产力，新接手项目或新公司需要重复踩坑。

1.2 产品目标

打造一款专为包装与制造供应链打造的 AI 智能 8D 报告协作平台，核心理念是"AI 做助手，人做决策"：

  1. 输入阶段：自动解析邮件正文、附件图片中的关键信息，输出 5W2H 摘要与精准的"补充资料清单"。
  2. 推演阶段：结合补充资料，进行证据链绑定的 5-Why 根因推演，每条推论标注置信度与来源。
  3. 判定阶段：AI 给出责任归属建议，由工程师通过确认框做最终决策。
  4. 生成阶段：确认后自动填充 D1~D8 标准卡片，支持逐卡编辑与局部 AI 重生成。
  5. 部署扩展：支持多租户隔离与双层知识库，可无缝赋能不同客户与新公司。

2 目标用户与使用场景

2.1 核心用户

质量工程师 (QE/QA)、供应链/采购经理、客服质量主管、工厂技术人员。

2.2 典型场景

场景触发条件系统行为
A. 初始接案 收到客户抱怨邮件与现场照片 解析邮件+图片 → 输出 5W2H 摘要 → 给出补充资料调取建议
B. 根因推演 补充数据到位（COA检测、物流记录等） 5-Why 证据链推演 → 置信度标注 → 推测项触发二次补充请求
C. 责任判定 证据链完整 AI 建议责任归属 → 工程师确认框确认 → 锁定结论
D. 报告结案 所有 D1~D8 确认完毕 一键导出标准格式 PDF/Word 8D 报告，提交客户或归档

3 系统核心功能规格

3.1 分步确认工作流（Step-by-Step Confirmation Workflow）

区别于传统"扔资料→出报告"的黑盒模式，系统采用 分步交互，每步产出需人工确认后才流入下一步：

┌─────────────────────────────────────────────────────────────┐ │ Step 1: 初分析与资料调取 │ │ 邮件/图片 ──► 多模态解析 ──► 输出 5W2H 摘要 + 补充资料清单 │ │ │ │ │ [用户确认/修改/补充上传] │ ├─────────────────────────────────────────────────────────────┤ │ Step 2: 根因推演（证据链绑定） │ │ 补充资料 ──► 5-Why 推演 ──► 输出每条推论的依据+置信度 │ │ │ │ │ [用户确认根因/修正推理] │ ├─────────────────────────────────────────────────────────────┤ │ Step 3: 责任判定 │ │ 已确认根因 ──► AI 责任建议 ──► 单选确认框 │ │ │ │ │ [工程师做最终决策] │ ├─────────────────────────────────────────────────────────────┤ │ Step 4: 8D 卡片渲染 │ │ 责任锁定 ──► 逐卡生成 D1~D8 ──► 每卡可编辑 + 局部AI重生成 │ │ │ │ │ [逐卡审核 → 一键导出] │ └─────────────────────────────────────────────────────────────┘
设计意图：分步确认天然创建了工作流的 check point。如果某一步资料不足或证据链断裂，用户在该步即可停下补充，不会浪费时间去确认后续步骤。体验上类似"有个经验丰富的 QA 在旁边跟你一起过案子"。

3.2 多模态输入解析（图片 + 邮件）

  • 邮件解析：支持粘贴邮件正文或拖入 .eml 文件，系统自动提取发件人、时间、正文内容及附件图片。
  • 图片分析：利用视觉大模型（Vision LLM）对上传的现场照片进行缺陷特征识别，包括但不限于：破损、划痕、塌箱、变形、印刷缺陷、受潮痕迹等。
  • 视频分析（暂缓）：视频解析涉及逐帧调用 Vision API，成本高且包装行业视频素材使用率低。Phase 1 不做，后续按需评估。
Phase 1 范围收敛：首版仅支持图片（JPG/PNG）+ 邮件文本（粘贴/eml）。PDF 附件暂通过用户手动粘贴关键段落的方式处理，自动化 PDF 解析列入 Phase 2。

3.3 双层知识库（RAG）+ LLM-as-ETL

第一层：公共行业知识库（Public Know-How Base）

  • 内容：预置包装/制造行业国家标准（GB/ISO/TAPPI）、通用 8D 规范、典型缺陷分析图谱。
  • 作用：确保系统即插即用，新公司即使零私有数据也能输出专业级分析。
  • 冷启动策略：由项目组一次性整理核心标准文档（约 20~50 份），通过标准 RAG 流水线向量化入库。

第二层：企业私有数据库（Private Tenant Base）

  • 内容：特定客户的历史 8D 报告、内部 SOP、产品规格书、供应商名册。
  • 隔离：通过 tenant_id 元数据标签实现多租户逻辑隔离（大客户可独立部署）。
  • 进化：每完成一份新 8D 报告，自动追加到私有库，随使用时间自我增强。

LLM-as-ETL：历史报告结构化管线

历史 8D 报告格式各异（Word/PDF/扫描件），传统正则方案维护成本高。采用 便宜大模型 + JSON Schema 方案：

历史8D报告 → 按D1~D8章节分段 → 便宜模型提取(DeepSeek/Qwen) → JSON Schema校验 │ ┌──────────────┴──────────────┐ │ 校验通过 → 向量化入库 │ │ 校验失败 → 错误信息回传模型重试 │ └─────────────────────────────┘
防御性设计要点：
① JSON Schema 严格校验，字段不合规自动重试（最多 3 次）
② 长报告按 D1~D8 章节分段提取，避免上下文过长导致精度下降
③ 模型选择：DeepSeek-V3 或 Qwen3-235B（中文好+便宜，性价比优于 GPT-4o-mini）

3.4 5-Why 根因推演（证据链绑定 + 置信度分级）

这是系统的核心推理引擎，采用 三条硬约束 确保输出可靠：

约束一：强制证据链绑定

每条推论必须附带引用来源，不允许凭空断言。输出格式：

{ "claim": "纸箱塌箱的根本原因为边压强度不达标", "why_chain": [ { "level": 1, "question": "为什么纸箱会塌？", "answer": "纸箱底部承压能力不足", "evidence": [ { "source": "COA检测报告_批次20260715.pdf 第3页", "excerpt": "边压强度实测值 3.2 kN/m，标准要求 ≥ 4.5 kN/m" }, { "source": "现场照片_DSC002.jpg", "description": "纸箱底部明显变形，呈现对称塌陷特征" } ] } // ... 更多层级 ], "root_cause": "供应商该批次纸板边压强度不达标", "confidence": "confirmed" }

约束二：置信度三级标注

级别含义触发行为
confirmed 有直接证据支持 正常推进下一步
inferred 多条证据组合推理得出，逻辑自洽但无直接证明 标注推理路径，建议人工复核
speculative 无直接或间接证据，属于 AI 推测 禁止作为结论使用，自动触发补充资料清单

约束三：推测自动触发补充资料清单

当某条推论置信度为 speculative 时，系统不输出结论，而是生成针对性的补充资料请求，例：

⚠️ 以下推论证据不足（speculative），暂不纳入结论：
"纸箱受潮可能是物流途中淋雨导致"
→ 请补充：① 物流签收单（核对签收时包装状态） ② 运输期间沿途天气记录 ③ 仓库温湿度日志

3.5 责任判定确认框（AI 建议 + 人工决策）

AI 仅给出建议，不做最终决策。工程师通过单选确认框选择或手动输入：

🏭 责任判定（请确认或修改）
以下为 AI 基于证据链给出的建议，请做出最终判定
◎ 供应商责任（AI 推荐）
依据：COA 边压强度不达标（3 条证据）| 来料检验记录缺失（2 条证据）
○ 客户方责任
依据：无直接证据支持
○ 设计缺陷
依据：无直接证据支持
○ 第三方（物流等）
依据：物流温湿度记录异常（1 条证据）| 置信度：inferred
✓ 确认判定 ✎ 手动输入理由
合规价值：AI 建议 + 人工确认的交互模式符合 ISO 9001 / IATF 16949 体系审核对"人做最终决策"的要求。确认操作记录可作为审计追踪日志保存。

3.6 8D 草案渲染与编辑

责任归属确认后，系统自动填充 D1~D8 结构卡片，每张卡片支持：

  • 直接编辑：点击卡片内任意文本区域直接修改
  • 局部 AI 重生成：单张卡片不满意可点击"AI 重新生成"按钮，仅刷新该卡片内容
  • 证据回链：卡片中每条关键结论旁标注来源引用，可点击查看原始资料
  • 一键导出：确认全部卡片后，导出为标准格式 PDF/Word 8D 报告

3.7 三栏界面设计（Three-Pane Workbench）

栏目名称核心功能
左栏 资料与空间管理 Workspace 下拉切换（租户/公司）、多模态客诉资料上传池（邮件文本粘贴、图片拖拽）、历史报告列表与状态跟踪、分步确认进度条
中栏 8D 标准文档画布 D1~D8 结构化卡片渲染、支持工程师直接在线编辑修改、单卡片"AI 局部重新生成"按钮、证据引用标注可点击溯源
右栏 AI 逻辑助手 可解释性面板（标注推导依据来源 + 置信度）、追问交互框（如"把 D3 围堵措施写得更具体些"）、责任判定确认框、补充资料清单管理
交互设计原则：三栏布局参考 IDE 工作台模式——左侧资源管理、中间文档编辑、右侧辅助分析。每步确认的状态变化在左栏进度的度条和右栏的结论面板中同步体现。

  • 统计分析看板（客诉趋势、供应商质量评分等）

5 关键风险与应对策略

#风险等级应对策略
1 幻觉与误判风险：LLM 在根因推演中编造因果链 高 强制证据链绑定 + 置信度三级标注 + speculative 项禁止作为结论 + Human-in-the-loop 确认机制
2 多模态识别准确率：包装缺陷图片分析不准确 中 持续优化 Vision Prompt，建立缺陷特征对比库；初期对模糊/低质量图片主动提示用户补充拍摄
3 API 成本失控：多模态+推理调用累积成本高 中 分层模型策略（强推理 vs 便宜 ETL 分开）；图片预处理压缩减分辨率；建立单案件成本上限告警
4 多租户数据安全：客户间数据隔离失效 高 检索层严格校验 tenant_id 元数据；大客户支持独立 Docker 部署；定期的隔离渗透测试
5 Dify 平台依赖：Dify 更新/故障影响平台稳定性 中 Phase 3 评估 Dify 独立部署方案的稳定性；核心 Prompt 和 RAG 逻辑与 Dify 解耦，预留迁移能力
6 历史报告 ETL 失败：LLM-as-ETL 输出不合规 JSON 低 jsonschema 校验 + 错误信息回传重试（最多 3 次）；最终兜底人工抽查
7 用户接受度：工程师不信任 AI 建议，使用率低 中 分步确认 + 证据链透明化建立信任；初期以 1-2 个品类做试点，用真实案例效果推动推广
